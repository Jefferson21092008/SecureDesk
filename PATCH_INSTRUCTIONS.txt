SecureDesk V0.4.2 — JWT, expiração e revogação
==============================================

Este patch deve ser aplicado sobre a V0.4.1 concluída.
A nova migration é 0011_add_revoked_tokens.

1. Confirme que a main está atualizada e crie a branch:
   git checkout main
   git pull origin main
   git checkout -b security/jwt-revocation

2. Extraia o conteúdo deste ZIP na raiz do SecureDesk, substituindo os arquivos existentes.

3. Recrie os containers sem remover volumes:
   docker compose down
   docker compose up --build -d

4. Confirme a migration:
   docker compose exec api alembic current

   Esperado:
   0011_add_revoked_tokens (head)

5. Rode os testes:
   docker compose exec api pytest -q

   Esperado nesta versão:
   117 passed

6. Rode o lint:
   docker compose exec api ruff check .

   Esperado:
   All checks passed!

7. Se tudo estiver verde:
   git add .
   git commit -m "security: add JWT revocation"
   git push -u origin security/jwt-revocation

Principais controles adicionados:
- JWT exige sub, jti, type, iat, exp, iss e aud;
- algoritmo de assinatura continua fixado pelo servidor;
- cada login gera um jti único;
- POST /auth/logout revoga o token atual;
- a blacklist grava o jti, nunca o JWT bruto;
- token revogado é rejeitado como inválido/expirado;
- revogação de uma sessão não encerra outras sessões;
- login retorna expires_in para o cliente;
- migration 0011_add_revoked_tokens adiciona persistência da blacklist.
