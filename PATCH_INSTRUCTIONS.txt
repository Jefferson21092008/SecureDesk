SecureDesk V0.3.4 - SLA and priority

1. Apply this patch over the project root while on branch:
   feat/ticket-sla

2. Rebuild and start Docker:
   docker compose down
   docker compose up --build -d

3. Confirm the migration:
   docker compose exec api alembic current

   Expected:
   0009_add_ticket_sla (head)

4. Run tests and lint:
   docker compose exec api pytest -q
   docker compose exec api ruff check .

   Expected baseline:
   80 passed
   All checks passed!

5. If everything is green:
   git add .
   git commit -m "feat: add ticket SLA"
   git push -u origin feat/ticket-sla

Baseline SLA policy in this version:
- HIGH: 4 hours
- MEDIUM: 8 hours
- LOW: 24 hours

Notes:
- sla_due_at is persisted in PostgreSQL and indexed.
- Changing priority recalculates the deadline from the original created_at; it does not restart the SLA clock.
- SLA status is ON_TRACK, MET or BREACHED.
- GET /tickets supports sla_status filtering and sla_due_at ordering.
- Existing tickets are backfilled by migration 0009 according to their priority and created_at.
