SecureDesk V0.4.3 — Rate limiting e proteção contra abuso
=========================================================

Este patch deve ser aplicado sobre a V0.4.2 concluída.
Esta etapa NÃO cria migration. O head continua sendo 0011_add_revoked_tokens.

1. Confirme que a main está atualizada e crie a branch:
   git checkout main
   git pull origin main
   git checkout -b security/rate-limiting

2. Extraia o conteúdo deste ZIP na raiz do SecureDesk, substituindo os arquivos existentes.

3. Recrie os containers sem remover volumes:
   docker compose down
   docker compose up --build -d

4. Confirme a migration:
   docker compose exec api alembic current

   Esperado:
   0011_add_revoked_tokens (head)

5. Rode os testes:
   docker compose exec api pytest -q

   Esperado nesta versão:
   128 passed

6. Rode o lint:
   docker compose exec api ruff check .

   Esperado:
   All checks passed!

7. Se tudo estiver verde:
   git add .
   git commit -m "security: add rate limiting and abuse protection"
   git push -u origin security/rate-limiting

Principais controles adicionados:
- limite global por cliente em janela deslizante;
- limite próprio para login e cadastro;
- bloqueio temporário após falhas repetidas de login;
- sucesso de login limpa o contador de falhas da conta/cliente;
- respostas 429 incluem Retry-After e metadados de limite;
- /health não consome quota do limiter;
- X-Forwarded-For não é confiado sem proxy explicitamente confiável;
- parâmetros de rate limiting configuráveis por variáveis de ambiente;
- contadores em memória, adequados ao processo único atual; produção multi-worker deve usar backend compartilhado.
